4. HIRA 최신 요율·요일별 가산 원문. 이번에는 잘못된 단정을 제거했을 뿐 현행 요율표를 검증·제공한 것이 아니다.
5. 요청한 두 식품 제품의 원문, 추출 결과, 삭제된 목록 제품의 직접 URL·색인 상태. UUID 직접 주소에서 한글 정규 주소로 이동할 때 발생한 Location 헤더 오류는 경로 인코딩으로 수정했다. 새 보수적 검증 때문에 과거 원문/섭취기준 없는 카드와 일부 sitemap 항목이 제외될 수 있다. 원문 보강이 필요하다.
6. 인프라 접근 로그 보관/파기, 이메일 실제 보관기간, GA4 Enhanced Measurement의 history/search 수집 설정, 광고 Auto ads·SPA 잔존·동의 관리. 인증 계정 접근 전 확정하지 않음.
7. GSC·GA4·백링크·CrUX 등 실제 성과·필드 데이터. 로컬 성능 수치를 운영 성과로 해석하지 않음.

## 검수 기록과 운영 반영 방법

`content/reviews/publication-reviews.json`은 의도적으로 빈 배열이다. 검수한 원문별로 `slug`, `contentReviewDigest(item)`의 SHA-256, 실제 `reviewer`, `scope`, `reviewed_at`, 직접 대응하는 HTTPS `sources`를 기록한다. 이 기록은 실무 절차의 추적 수단이며 자격·전문성을 자동 보증하지 않는다. 본문·FAQ·요약·이미지·HPID가 바뀌면 이전 검수를 재사용할 수 없다. 의료 주장은 실제 자격·검수 범위를 운영자가 확인해야 한다. 미래 검수일·빈 신원·출처 없는 검수는 발행 불가다.

검수 기록을 만든다고 review가 자동 공개되지 않는다. 운영자가 검수 범위와 예약 시각을 확인해 pending으로 승인해야 하며, 이번 작업은 그 운영 변경을 수행하지 않았다. 해시를 맞추기 위해 가상의 검수 기록을 넣지 않는다.

## 검증 결과

빈 검색이 별도 동의 없이 GPS 요청으로 이어지던 동작도 입력 안내로 수정했다.

최종 명령과 브라우저 결과는 `VALIDATION.md` 및 `browser-smoke.json`에 별도로 기록한다. 이전 실패와 수정 원인도 구분한다. 코드 배포 준비와 Git 푸시, 운영 배포 성공, 애드센스 심사는 각각 다른 상태다.
