브라우저 실행은 기본 설정의 다운로드 Chromium 대신 기존 `/usr/bin/chromium`을 사용했고, API를 실제 운영 데이터로 바꾸지 않았다. CI 기본 구성에서의 실행은 아직 관측하지 않았다.

추가 회귀 검증은 `tests/unit/{hours-readiness,readiness,publication-review}.test.ts`, `tests/e2e/readiness.spec.ts`에 있다. 발행 경쟁 검사는 실제 메모리 SQLite를 사용해 검수 이후 본문 변경 시 claim이 실패하는지 확인한다. 현재 운영 큐 발행은 실행하지 않았다.

## 발견·수정 후 다시 확인한 실패

- 최초 unit 실패: 기존 정책 테스트가 전역 광고 스크립트/외부 추정 통계를 요구하던 조건. 새 요청과 충돌한 조건을 검증 가능한 출처·광고 제한으로 교체했다.
- 브라우저 7개 실패: 현재 UI와 다른 과거 검색 placeholder·네비게이션 라벨·닫힌 모바일 메뉴를 가정하던 테스트. 실제 UI를 확인해 테스트를 바로잡은 뒤 38개 전체 통과.
- 빈 검색 회귀: 위치 API 요청으로 전환되는 동작을 실패 테스트로 재현하고, 입력 오류 안내로 고친 뒤 모바일/데스크톱 통과.
- 로컬 제품 fixture의 중복 신고번호가 첫 표본을 대체한 설정 오류를 수정했다. 이 실패는 운영 제품 오류의 증거로 기록하지 않았다.
- UUID 직접 제품 URL의 비ASCII Location 500을 재현하고 정규 경로 인코딩으로 수정했다. 식품·의약품 경로 생성기에 회귀 검증을 추가했다.
- 빌드 시 DB가 없는 상태의 사이트맵 ID가 고정되는 것을 확인하고, 캐시된 런타임 데이터 조회와 새 품질 정책 캐시 키로 변경한 후 표본의 유효 제품만 sitemap에 포함됨을 확인했다.
- 접힌 원문 `<details>`는 실제로 펼친 뒤 확인했다. 숨겨진 원문을 보이는 본문처럼 취급하지 않았다.

## 성능·증거 파일

- `browser-smoke.json`: 16개 반응형 확인 결과. 약국 ID `TEST-READINESS`는 실제 약국이 아닌 로컬 표본이다.
- `product-smoke.json`: 함량 근거 있는/없는 두 로컬 표본과 sitemap 정합성.
- `local-performance.json`: 홈·임신 글·약국 표본 × 390/1366px의 로컬 TTFB/LCP/CLS 측정값. 단일 비제한 Chromium, 로컬 SQLite, 외부 스크립트 차단 조건이다. 운영 Core Web Vitals나 승인 점수가 아니다.
- 원본 로그·검증 helper·390px 스크린샷은 저장소 외부 `/workspace/scratch/today-yakuk-readiness-2026-11-03/`에 보관했다. 운영 토큰·개인 문의 데이터는 포함하지 않았다.
